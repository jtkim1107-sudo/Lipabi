# Lipabi — Power BI 데이터 AI 아침 분석 & 팀 칸반보드

매일 아침 Power BI 데이터를 자동으로 불러와 AI(Claude)가 분석하고,
그 결과를 **업무 카드**로 만들어 직원들과 함께 칸반보드에서 관리하는 시스템입니다.

```
┌─────────────┐    매일 아침 07:00    ┌──────────────┐         ┌──────────────────────┐
│  Power BI    │ ──── DAX 쿼리 ────▶ │  Claude AI    │ ──────▶ │  칸반보드 (웹)         │
│  데이터셋     │                     │  분석/업무 제안 │         │  AI 제안→할 일→진행→완료 │
└─────────────┘                     └──────────────┘         └──────────────────────┘
```

- **자동 수집**: `config/queries.json`에 정의한 DAX 쿼리를 Power BI REST API로 실행
- **AI 분석**: 요약 + 인사이트 + "오늘 할 업무" 제안을 생성
- **칸반보드**: AI 제안이 카드로 자동 등록 → 직원들이 드래그해서 담당자 지정, 진행 관리
- **스케줄러 내장**: 서버만 켜두면 매일 아침 자동 실행 (기본 07:00 KST)

## 1. 빠른 시작 (Power BI 연동 없이 체험)

Power BI 설정 전에도 샘플 데이터로 전체 흐름을 바로 볼 수 있습니다.

```bash
# 1) 의존성 설치
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt

# 2) 환경 변수 설정
cp .env.example .env
# .env 파일을 열어 ANTHROPIC_API_KEY만 입력 (POWERBI_MOCK=true 유지)

# 3) 서버 실행
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

브라우저에서 `http://localhost:8000` 접속 → **[지금 분석 실행]** 버튼 클릭
→ 샘플 매출 데이터를 AI가 분석해 업무 카드가 생성됩니다.

> Claude API 키는 https://console.anthropic.com 에서 발급합니다.

## 2. Power BI 실제 연동

### 2-1. Azure AD 앱 등록 (서비스 주체)

1. [Azure Portal](https://portal.azure.com) → **Microsoft Entra ID** → **앱 등록** → **새 등록**
2. 등록 후 **개요**에서 다음 값을 복사해 `.env`에 입력
   - 애플리케이션(클라이언트) ID → `POWERBI_CLIENT_ID`
   - 디렉터리(테넌트) ID → `POWERBI_TENANT_ID`
3. **인증서 및 비밀** → **새 클라이언트 비밀** 생성 → 값 복사 → `POWERBI_CLIENT_SECRET`
4. Microsoft Entra ID에서 **보안 그룹**을 하나 만들고 이 앱을 멤버로 추가

### 2-2. Power BI 관리 설정

1. [Power BI 관리 포털](https://app.powerbi.com/admin-portal/tenantSettings) → **테넌트 설정**
   → **개발자 설정** → **서비스 주체가 Power BI API를 사용할 수 있음** 활성화
   → 위에서 만든 보안 그룹에 적용
2. 데이터가 있는 **작업 영역** → **액세스 관리** → 보안 그룹(또는 앱)을 **구성원** 이상으로 추가

### 2-3. 쿼리 정의

`config/queries.json`에 매일 불러올 데이터를 DAX로 정의합니다.

- `dataset_id`: Power BI에서 데이터셋을 열었을 때 URL의 `datasets/` 뒤 ID
- `workspace_id`: 작업 영역 URL의 `groups/` 뒤 ID (내 작업 영역이면 빈 문자열)
- `dax`: `EVALUATE`로 시작하는 DAX 쿼리 (Power BI Desktop의 DAX 쿼리 뷰에서 테스트 가능)

설정이 끝나면 `.env`에서 `POWERBI_MOCK=false`로 변경합니다.

## 4. 로그인과 보안

모든 화면과 API는 **로그인해야만** 사용할 수 있습니다.

### 최초 관리자 계정

서버를 처음 실행하면 관리자 계정이 자동 생성됩니다.

- `.env`에 `ADMIN_PASSWORD`를 설정했으면 그 비밀번호로 생성
- 설정하지 않았으면 **임시 비밀번호가 무작위 생성되어 서버 로그에 출력**됩니다
  (`관리자 계정이 생성되었습니다 → 아이디: admin / 임시 비밀번호: ...`)

### 직원 계정 관리

관리자로 로그인하면 우상단 **[직원 관리]**에서:
- 직원 계정 추가 (아이디/이름/팀/비밀번호/역할)
- 팀·역할 인라인 변경, 비밀번호 재설정, 계정 삭제
  (자기 자신과 마지막 관리자는 삭제/강등 불가)

역할은 3단계입니다:

| 역할 | 권한 |
|------|------|
| **관리자** (admin) | 전부 — 직원 관리, 전사 분석가 교육 |
| **팀장** (leader) | 직원 권한 + 팀 단위 브리핑 (팀원 부하/위임 제안) |
| **직원** (member) | 보드 사용, 내 에이전트, 오늘 브리핑 |

### 적용된 보안 장치

| 항목 | 내용 |
|------|------|
| 비밀번호 저장 | PBKDF2-SHA256 600,000회 해시 + 솔트 (평문 저장 안 함) |
| 세션 | 서버 저장 무작위 토큰, HttpOnly + SameSite=Lax 쿠키, 기본 14일 만료 |
| 로그인 시도 제한 | IP+아이디 기준 15분 내 5회 실패 시 잠금 |
| 비밀번호 변경 | 변경/재설정 시 해당 사용자의 기존 세션 전부 무효화 |
| 자동화 API | `/api/run`은 로그인 세션 또는 `X-Run-Token` 헤더로만 호출 가능 |
| HTTPS | 리버스 프록시(nginx, Caddy 등) 뒤에서 `COOKIE_SECURE=true` 설정 권장 |

> 참고: 인터넷에 공개할 경우 반드시 HTTPS를 적용하세요. 사내망 전용이라면
> 기본 설정으로도 충분합니다.

## 5. 나의 분석가 교육하기

AI 분석가를 **나의 판단 기준대로 일하도록** 키울 수 있습니다. 관리자로 로그인하면
우상단 **[내 분석가]** 메뉴가 열립니다.

### 지침 작성 (직접 가르치기)

"나의 지침"에 회사의 관점과 기준을 자유롭게 적으면 **다음 분석부터 바로 반영**됩니다.

```
예)
- 우리 회사는 재고 회전율을 매출보다 중요하게 본다
- 업무 지시는 담당 팀(영업/재고/마케팅)을 명시할 것
- 광고비 관련 제안은 주 단위 예산 한도 내에서만
- 숫자는 반드시 전주 대비 %로 표현
```

### 피드백으로 가르치기 (쓰면서 자동 수집)

평소에 보드를 쓰는 행동이 그대로 학습 신호가 됩니다.

| 행동 | 학습 신호 |
|------|-----------|
| AI 제안 카드를 **할 일로 드래그** (수락) | 긍정 — "이런 제안이 좋다" |
| AI 제안 카드를 **삭제** (+이유 입력 가능) | 부정 — "이런 제안은 하지 마라" |
| 리포트에 **👍 좋아요 / 👎 아쉬워요** (+코멘트) | 분석 스타일 피드백 |

### 학습 실행

[내 분석가]에서 **[피드백 학습하기]**를 누르면 쌓인 피드백을 AI가 일반화된
"교훈" 목록으로 정리해 저장합니다. 이후 매일 아침 분석은
`기본 원칙 + 나의 지침 + 학습된 교훈`을 모두 반영해 수행됩니다.
피드백이 쌓일수록 분석가가 점점 운영자의 판단을 닮아갑니다.

### 직원 개인 에이전트

전사 분석가와 별개로, **모든 직원이 자기만의 에이전트**를 가집니다.

- **[내 에이전트]**: 자기 역할과 선호를 작성 ("나는 마케팅 담당, 오전엔 집중 업무" 등).
  본인이 수락/삭제한 카드와 남긴 피드백이 자기 에이전트의 학습 신호로도 쌓이며,
  [피드백 학습하기]로 "나에 대해 학습한 내용"이 정리됩니다.
- **[오늘 브리핑]**: 에이전트가 아침 분석과 보드 현황을 보고 "오늘 이 사람이
  집중할 일 3~5개"를 개인화해서 만들어 줍니다. 하루 한 번 생성 후 캐시되며
  [다시 생성]으로 갱신할 수 있습니다.
- **팀장 브리핑**: 역할이 팀장이고 팀이 지정돼 있으면, 브리핑이 팀 전체 관점으로
  바뀝니다 — 팀원별 업무 부하, 정체된 카드, 미배정 제안을 짚고
  "이 업무는 ○○에게" 식의 **추천 담당** 위임 제안까지 포함합니다.

### 업무 대체 — AI가 직접 일합니다

- **AI 수행**: 카드의 🤖 **[AI 수행]** 버튼을 누르면 AI가 그 업무를 직접 수행해
  결과물(보고서·이메일 초안·체크리스트·분석 요약 등)을 만들어 카드에 첨부합니다.
  직원은 **[결과 보기]**에서 검토 후 복사해 쓰거나 [완료로 이동]하면 됩니다.
  외부 확인이 필요한 부분은 결과물 안에 `[확인 필요: ...]`로 표시됩니다.
- **자동 담당 추천**: 아침 분석이 업무를 제안할 때 직원 명단(역할·팀)을 보고
  적임자를 추천합니다. AI 제안 카드의 "추천: ○○" 배지를 클릭하면 바로 배정됩니다.

### 부족한 데이터는 분석가가 직접 요청합니다

분석 중 "이 데이터가 없어서 판단이 제한된다"고 판단하면, 분석가가 **데이터 요청**을
남깁니다 — 무엇이 필요한지, 있으면 어떤 판단이 가능해지는지, Power BI에 있을 법한
데이터면 예시 DAX 쿼리까지.

- 리포트 패널의 **"분석가가 요청한 데이터"** 목록에 표시됩니다 (전 직원 열람 가능)
- 관리자는 요청별로 처리합니다:
  - **[업무로 만들기]** — "데이터 연결: ..." 카드가 할 일에 생성됨 (제안 DAX 포함)
  - **[해결됨]** — 쿼리를 추가했으면 해결 처리 (이후 데이터가 여전히 없으면 다시 요청됨)
  - **[무시]** — 필요 없는 요청 정리
- 대기 중인 요청은 다음 분석 때 프롬프트에 전달되어 **같은 요청이 중복 생성되지 않습니다**
- **분석 차단(blocking) 요청**: "이 데이터가 없으면 오늘의 핵심 질문(급락 원인 등)에
  답할 수 없다" 수준이면 분석가가 차단 표시를 하고, 관리자 확인 없이 **즉시 높은
  우선순위 '데이터 연결' 업무가 자동 생성**됩니다. 리포트에는
  "⚠️ 데이터 부족으로 일부 분석이 제한되고 있습니다" 경고가 표시됩니다.

예를 들어 화요일 오후 주문 급감이 반복되는데 광고 데이터가 연결돼 있지 않으면:
인사이트에 *"광고 집행 시간대가 원인인지 광고 데이터가 없어 확인 불가"* 라고 명시되고,
*"광고 채널별 시간대별 집행 내역"* 이 분석 차단 요청으로 올라오며,
할 일 열에 높은 우선순위 데이터 연결 카드가 자동으로 생성됩니다.

### 자기 채점 — 사람이 없어도 데이터로 배웁니다

매일 아침 분석 전에, 분석가가 **어제 자신이 낸 인사이트를 오늘 실제 데이터와 대조**해
스스로 채점합니다 (`SELF_REVIEW=true`, 기본 켜짐).

- 인사이트별로 ✓ 맞음 / ✗ 틀림 / ─ 확인 불가 판정 + 오늘 수치를 인용한 근거
- 리포트 패널의 **"어제 분석 채점"**에 적중률과 함께 표시 — 분석가의 실력이 투명하게 보입니다
- 틀린 판정은 **일반화된 교훈**으로 추출되어 피드백에 자동 축적 → 주간 학습 때 반영
- 채점 결과가 당일 분석 프롬프트에 주입되어 **같은 유형의 실수를 바로 그날부터 회피**

사람 피드백(수락/삭제/좋아요) 없이도, 데이터만으로 매일 교정되는 학습 루프입니다.

### 보고 자동화 — 보고서를 쓰지 않아도 보고가 됩니다

보고가 잘 안 되는 조직을 위해, **보고를 시키는 대신 보고가 저절로 만들어지는** 구조입니다.

- **활동 자동 기록**: 카드 생성·이동·배정·완료·AI 수행이 전부 자동으로 기록됩니다.
  직원이 보고를 위해 따로 할 일이 없습니다.
- **진행 메모 (💬)**: 카드에 한 줄 메모만 남기면 그게 곧 보고가 됩니다.
- **막힘 표시 (⛔)**: 메모에 "막힘/도움 필요"를 체크하면 카드에 빨간 배지가 붙고,
  팀장 브리핑과 일일 보고에 바로 올라갑니다 — 막힌 걸 숨기지 못하는 구조.
- **일일 업무 보고 자동 생성**: 매일 저녁(기본 18:00, `DAILY_REPORT_TIME`) AI가 하루
  활동을 모아 경영진용 보고를 작성합니다 — 전체 요약 / 주요 진전 / **막힘·조치 필요** /
  사람별 현황. 상단 [업무 보고]에서 전 직원이 열람하고, 팀장·관리자는 [지금 생성]으로
  즉시 만들 수도 있습니다.

보고 프롬프트 원칙: 기록된 사실만, 부풀리지 않기, 막힘 숨기지 않기,
활동 없는 사람 지적하지 않기 (보고의 목적은 질책이 아니라 제때 조치).

### 자동화 스케줄

| 시점 | 자동 실행 | 설정 |
|------|-----------|------|
| 매일 아침 (기본 07:00) | 데이터 수집 → **어제 분석 자기 채점** → 분석 → 업무 등록 → **전 직원 브리핑 생성** | `DAILY_RUN_TIME`, `SELF_REVIEW`, `AUTO_BRIEFINGS` |
| 매일 저녁 (기본 18:00) | 하루 활동 → **일일 업무 보고 자동 생성** | `DAILY_REPORT_TIME` (비우면 끔) |
| 매주 (기본 월 06:30) | 전사 분석가 + 모든 개인 에이전트 **자동 학습** | `WEEKLY_TRAIN` (비우면 끔) |

즉, 서버만 켜두면: 출근 → 보드에 오늘 업무와 내 브리핑이 이미 준비돼 있고,
지난주의 피드백은 월요일마다 자동으로 에이전트에 반영됩니다.

## 6. 팀에서 함께 쓰기

- 서버를 사내망(또는 클라우드)에 띄우고 직원들에게 주소를 공유하면 됩니다.
- 관리자가 직원 계정을 만들어 주면 각자 로그인해서 사용합니다.
- 보드는 15초마다 자동 새로고침되어 서로의 변경 사항이 반영됩니다.
- 카드 사용법:
  - **AI 제안** 열에 매일 아침 분석 결과 업무가 올라옵니다
  - 진행할 업무를 **할 일**로 드래그하고 카드의 담당자 칸에 이름 입력
  - 작업 상황에 따라 **진행 중 → 완료**로 이동
  - 필요 없는 제안은 ✕로 삭제, 수동 업무는 할 일 열의 ＋ 버튼으로 추가

## 7. 구조

```
Lipabi/
├── app/
│   ├── main.py        # FastAPI 서버 + 아침 스케줄러
│   ├── pipeline.py    # 수집 → 분석 → 업무 등록 파이프라인
│   ├── powerbi.py     # Power BI REST API (MSAL 인증, DAX 실행)
│   ├── analyzer.py    # Claude AI 분석 (지침+교훈 반영, 구조화된 JSON 출력)
│   ├── coach.py       # 에이전트 교육 (전사/개인 피드백 → 교훈 정리)
│   ├── briefer.py     # 직원별 오늘 브리핑 생성
│   ├── worker.py      # AI 실무 수행 (업무 → 결과물 초안)
│   ├── reviewer.py    # 자기 채점 (어제 인사이트 vs 오늘 데이터)
│   ├── reporter.py    # 일일 업무 보고 자동 생성 (활동 로그 → 보고)
│   ├── database.py    # SQLite 저장소 (사용자, 세션, 리포트, 업무)
│   ├── auth.py        # 비밀번호 해시, 세션 토큰, 로그인 시도 제한
│   ├── config.py      # 환경 변수 설정
│   └── static/        # 칸반보드 웹 UI (index.html, login.html)
├── config/queries.json  # 매일 불러올 DAX 쿼리 정의
├── run_daily.py         # cron/수동 실행용 스크립트
└── .github/workflows/daily-analysis.yml  # (선택) GitHub Actions 스케줄
```
